# HOPE App – Team Working Agreement, Definition of Done, and Role Guide

**Task ID:** S1-SM-03  
**Project:** HOPE App ERP System  
**Prepared by:** Trisvan600 (Scrum Master)

## 1. Team Working Agreement

Our team agrees to follow these rules throughout the project:

1. Communicate through our group chat for updates and concerns.
2. Attend scheduled meetings and inform the team if unavailable.
3. Update assigned tasks on our GitHub Project board.
4. Report problems or blockers to the team as soon as possible.
5. Help teammates when needed and respect everyone's ideas.
6. Create a Pull Request (PR) for repository changes and ask another member to review it before merging.

## 2. Definition of Done (DoD)

A task is considered complete when:

- The assigned work meets its acceptance criteria.
- The feature has been tested, or the document has been checked for errors.
- The necessary files are uploaded to GitHub.
- The Pull Request is reviewed, approved, and merged, if required.
- The GitHub Issue and Project board are updated to Done.

## 3. Team Role Guide

| Role | Responsibilities |
|---|---|
| **Developer** | Develops the system features and fixes code errors. |
| **Database Administrator (DBA)** | Manages the database and Supabase integration. |
| **Tester** | Tests the system, reports bugs, and checks fixes. |
| **UI/UX Designer** | Designs the system interface and improves usability. |
| **Scrum Master** | Organizes sprint tasks, monitors progress, facilitates meetings, and helps resolve blockers. |

**Note:** These five roles describe our project team's responsibilities. They are different from the ERP system's account roles (Superadmin, Admin, and User) described in the HOPE App Student Guide.

## 4. Team Review

This document will be reviewed by the team to make sure everyone understands their responsibilities and agrees with the working rules.
